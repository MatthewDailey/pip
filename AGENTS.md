# AGENTS.md

Canonical instructions for every coding agent in this repo (Claude Code reads them through `CLAUDE.md`, Codex and
others read this file). [README.md](README.md) is the human tour; this file is what an agent needs to work safely.

## What this is

**shady-pip** holds Pip, a personal cyber defense agent for Android, and the tools around him: the Pip Android app,
rivc (our compiler from JSON + SVG to Rive `.riv`), a browser previewer, and Pip's Rive sources. Pip is written as
text and compiled; nobody opens the Rive editor.

## Setup

macOS on Apple Silicon with Homebrew and Node 24 (`.nvmrc`). One command bootstraps everything (JDK 21, the Android
SDK and the `Pip_API_37` AVD, pnpm, the Python venv, Playwright's Chromium) and installs only what is missing:

```sh
npx turbo dev            # first time; afterwards: turbo dev, turbo droid (Android only), turbo jev, turbo demo
bash scripts/setup.sh    # the same bootstrap without starting anything; --force redoes it
```

In a fresh clone the turbo CLI isn't installed yet: use `npx turbo ...` (for any command below) until setup has
installed it, then plain `turbo`. Every turbo task runs `//#setup` first, so `npx turbo run <task>` works in a fresh
clone. The first rivc use (a preview, a build, `rive:rig`) builds rivc with Gradle, about 8 minutes cold; run it in
the background or wait it out, and don't kill it as hung. Use pnpm (`pnpm install` at
the root, workspace members by `--filter`); never `npm install`. Copy `.env.example` to `.env` only for the live
scam caller.

## Animating Pip

To change Pip's rig (moods, blinks, glances, new inputs) or make a new story (a short scene like HODOR), follow the
**`animating-pip` skill**: [`.claude/skills/animating-pip/SKILL.md`](.claude/skills/animating-pip/SKILL.md) (also at
`.agents/skills/animating-pip` for Codex). In short:

- `packages/pip-rive/pip/build-pip.mjs` is the rig's source; `pip.json`, `pip-inputs.json` and `pip.svg` are
  generated. Rive layers replace rather than add, so every property has one owning layer.
- A story is a rivc project in `packages/pip-rive/stories/<name>/<name>.json`; copy `stories/hello`.
- Iterate in the previewer, guard with goldens, then push the `.riv` to `/sdcard/Download/` and play it without
  reinstalling.

## Scenarios

`turbo run scenarios` is the stage for Pip's overlay reactions: for each moment in the re-skin mocks it sets up the
real situation on the emulator (a ringing or live scripted call, a text, a notification, a page in Chrome, a fixture
app with the keyboard up), waits until you close it, tears it down, and prints what Pip should do (from the re-skin
ref's trigger map) next to what Pip did (read from his event log), with a screenshot in `.proof/scenarios/`.

- **Add a scenario** by adding an entry to `apps/pip-scenarios/scenarios.json`: `steps` (listed at the top of
  `lib/steps.mjs`), optional `auto` steps that stand in for the person in `auto=` runs, `done` conditions (listed in
  `lib/device.mjs`), the mock it matches and the trigger map's `expect`. Mark it `approximated` with a `why` when the
  emulator can't stage it exactly, and name the missing app hook in `seam`.
- **Fictional only:** brands, people and numbers in scenarios, `web/` pages and fixtures are made up ("Bank of
  Example", 555 numbers). Pages are served from `web/` to Chrome through `adb reverse`; their forms send nothing.
- **Fixture screens** live in `apps/pip-fixtures` (plain Views, no dependencies); a scenario opens one with
  `{ "do": "fixture", "activity": "MailActivity", "extras": { ... } }`.
- **Calls:** a scripted caller must close its mic stream before the call ends, or the emulator segfaults; run calls
  through the `mock-call` step (or `mock_call.sh`), which hangs up in that order.

## Rules

- **Commits:** stage explicit paths (`git add path/a path/b`), never `git add -A` or `git add .`: other agents share
  this machine and its worktrees. Never list an agent as author or co-author, in commits or PR text.
- **No secrets:** never commit `.env`, keys, tokens or `local.properties`.
- **Generated files:** don't hand-edit `packages/pip-rive/pip/pip*.json|svg`, `packages/pip-rive/showreel/*.json`
  or `showreel/gen/`; change their generator.
- **The emulator is shared.** Several agents use the one running emulator (`emulator-5554`). Never restart, wipe or
  cold-boot it, never uninstall the app (so don't run `turbo demo`, which reinstalls it fresh, unless asked), and never start `screenrecord` while another one runs: check
  `adb shell pidof screenrecord` prints nothing first. Prefer pushing a `.riv` to `/sdcard/Download/` over
  reinstalling.
- **Restore accessibility settings.** `app:setup` adds the Pip app's service to `enabled_accessibility_services`
  rather than replacing the list. If you change that setting (or `accessibility_enabled`) for a test, save the old
  value first (`adb shell settings get secure enabled_accessibility_services`) and put it back when you are done.
- **Proof** (screenshots, videos) goes in `.proof/`, which is gitignored; never commit it.
- **Docs:** `docs/` write-ups are point-in-time; the code is the source of truth. Keep this file and the skill
  current when you change a command or a path they name.
