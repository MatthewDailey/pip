# pip-rive

Pip's Rive sources and the `.riv` files rivc compiles from them. It has no Android code, so it builds and
previews on its own; the Pip app consumes its output.

| Folder | What it holds |
| --- | --- |
| `pip/` | The overlay's Pip rig: `pip.json` (driven by the `Pip` view model), `pip-inputs.json` (the same rig on state-machine inputs, nested in the showreel) and `pip.svg`, all generated by `build-pip.mjs` |
| `showreel/` | `showreel.json` and `hodor.json`, written by `packages/showreel-to-rivc` from the Kotlin showreel's export, with their fonts, generated pieces (`gen/`) and coverage reports |
| `stories/` | Short hand-written stories, one rivc project per folder (`stories/<name>/<name>.json`); `hello/` is the worked example. How to write one: the `animating-pip` skill (`.claude/skills/animating-pip/SKILL.md`) |
| `sets/` | Set-piece SVGs and motion drafts drawn by `tools/pip-art` |

```sh
turbo run build --filter=@shady-pip/pip-rive   # compile into dist/ (cached on the sources)
turbo run rive:rig                             # regenerate pip/ from build-pip.mjs
```

`dist/` is gitignored and mirrors the app's asset paths (`pip/pip.riv`, `showreel/showreel.riv`,
`showreel/hodor.riv`, and `showreel/<story>.riv` for each story). The app adds it as an assets folder, so the app's build, test, lint and install tasks (and `turbo droid`)
compile these first.
